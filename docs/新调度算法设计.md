# 新调度算法设计：CRISP

CRISP（Computation-network Resource-aware Insertion and Short-term Promotion）是一种面向 AI 训推混部集群的算网协同调度算法。算法以 `算法.docx` 中的插队理论、多优先级队列、SLA 偏移和多维资源碎片化建模为基础，同时吸收算网共同碎片化量与实验评价文档中的指标体系，目标是在保障推理尾延迟的前提下，通过短时通信提权改变训练任务完成顺序，降低运行时算网共同碎片化量。

## 1. 设计动机

现有动态优先级方法通常只关注局部网络状态，例如队列长度、CNP 频率或流完成时间；CRUX-like 方法则偏向加速高 GPU 强度任务。这两类方法都容易忽略一个关键事实：任务的通信完成顺序会决定 GPU、主机、ToR 域和跨域带宽资源的释放轨迹。若低优先级少卡长尾任务长期占用关键位置，即使集群总空闲 GPU 数充足，也可能无法形成满足后续大任务通信需求的连续算网资源块。

CRISP 的核心思想是：优先级不应只表示业务类型或 GPU 规模，而应表示某个任务在当前状态下对系统未来可调度性的边际贡献。一个任务只有在“即将完成、释放关键算网资源、不会破坏推理 SLA、不会显著加剧 PFC/队列拥塞”时，才获得短时通信提权。

## 2. 系统状态与输入

在调度周期 `t`，系统状态表示为：

$$
X_t=(C_t,N_t,Q_t,R_t)
$$

其中：

- $C_t$ 表示 GPU、主机、ToR、Pod 等计算资源占用状态；
- $N_t$ 表示链路剩余带宽、路径时延、交换层级和 ECN/CNP 状态；
- $Q_t$ 表示各端口、各优先级队列长度、速率和缓冲区水位；
- $R_t$ 表示运行中任务的剩余计算量、剩余通信量、已运行时间和历史进度。

对每个运行中任务 $j$，调度器维护以下信息：

- 任务类型：训练任务或推理任务；
- GPU 放置集合 $A_j$；
- 通信模式：AllReduce、Parameter Server、Pipeline Parallel 或推理请求流；
- 剩余通信量 $\hat{B}^{rem}_j(t)$；
- 预计剩余完成时间 $\hat{T}^{rem}_j(t)$；
- 基础优先级 $P^{base}_j$；
- SLA 截止时间或 TTFT/TPOT 约束；
- 当前 QP/flow 所在优先级队列。

## 3. 算网释放收益

首先沿用算网共同碎片化量：

$$
F_{\text{cn}}(X_t)
=
1-\sum_{m\in \mathcal{M}}p_m U_m(X_t)
$$

其中 $U_m(X_t)$ 表示当前状态下未来任务类型 $m$ 是否能够找到满足 GPU 数量、带宽和延迟约束的有效资源块。

若假设任务 $j$ 被优先完成并释放资源，则状态变为：

$$
X_t^{(-j)}=\text{Release}(X_t,j)
$$

任务 $j$ 的算网释放收益定义为：

$$
G_j(t)=
\sum_{m\in \mathcal{M}}p_m
\left[
U_m(X_t^{(-j)})-U_m(X_t)
\right]
$$

该收益越大，说明任务 $j$ 提前完成越能提高后续任务的可调度性。与只看 GPU 数量不同，$G_j(t)$ 会更偏向释放完整 8-GPU 主机、同 ToR 高速资源块或关键跨域链路瓶颈的任务。

## 4. 贝叶斯剩余时间估计

为了避免长剩余时间任务长期占据高优先级队列，CRISP 使用条件剩余时间估计：

$$
\hat{T}^{rem}_j(t)
=
\mathbb{E}
\left[
T_j-t_j^{run}
\mid
T_j>t_j^{run}, type(j)
\right]
$$

其中 $t_j^{run}$ 为任务已运行时间。实现时可用历史同类型任务生命周期分布离散近似：

$$
\hat{T}^{rem}_j(t)
\approx
\frac{
\sum_{\tau=t_j^{run}}^{T_{max}}
(\tau-t_j^{run}) f_{type(j)}(\tau)
}{
\sum_{\tau=t_j^{run}}^{T_{max}}
f_{type(j)}(\tau)
+\epsilon
}
$$

在网络侧，还需要结合当前路径带宽和队列等待修正：

$$
\hat{T}^{net}_j(t)
=
\frac{\hat{B}^{rem}_j(t)}
{\hat{b}_j(t)+\epsilon}
+
\hat{W}_{q,j}(t)
$$

最终剩余时间取计算侧与网络侧的较大值：

$$
\hat{T}^{rem}_j(t)=
\max(\hat{T}^{life}_j(t), \hat{T}^{net}_j(t))
$$

## 5. 单位时间碎片化收益

CRISP 不直接使用 $G_j(t)$，而是使用单位时间收益：

$$
E_j(t)=
\frac{G_j(t)}
{\hat{T}^{rem}_j(t)+\epsilon}
$$

这样可以优先选择“释放收益高且接近完成”的任务，避免大任务或长尾任务因一次高收益评估而长期占用高优先级队列。

## 6. 插队代价与网络干扰

根据 `算法.docx` 中单优先级插队与多优先级队列的对偶关系，若将任务 $j$ 的通信流插入到优先级队列 $p$，会对当前队列中其他流产生等待时间增量。CRISP 将该增量抽象为插队代价：

$$
C^{ins}_{j,p}(t)
=
\sum_{f\in \mathcal{Q}_{\ge p}}
\omega_f
\cdot
\Delta W_f(j,p,t)
$$

其中 $\mathcal{Q}_{\ge p}$ 表示会被该提权影响的同级或低级队列流，$\omega_f$ 为业务权重，$\Delta W_f$ 为插入任务 $j$ 后的等待时间增量。

同时定义网络干扰成本：

$$
I_{j,p}(t)
=
\lambda_1 C^{ins}_{j,p}(t)
+
\lambda_2 H_p(t)
+
\lambda_3 CNP_p(t)
+
\lambda_4 PFC_p(t)
$$

其中 $H_p(t)$ 为队列水位接近高水位阈值的程度，$CNP_p(t)$ 为拥塞通知强度，$PFC_p(t)$ 为 PFC 风险。该项用于防止短时提权演化为高优先级队列拥塞。

## 7. SLA 压力与外部 RTT 偏移

对于推理任务 $j$，SLA 压力定义为：

$$
S_j(t)
=
\max
\left(
0,
\frac{
T^{int}_{need,j}(t)-T^{int}_{allow,j}(t)
}{
T^{sla}_j+\epsilon
}
\right)
$$

其中：

$$
T^{int}_{allow,j}(t)
=
T^{sla}_j
-
T^{ext}_{spent,j}(t)
-
T^{compute}_{remain,j}(t)
$$

$T^{ext}_{spent,j}(t)$ 表示已经消耗的外部 RTT 或网外时延。若外部 RTT 较大，内部网络可用时间减少，$S_j(t)$ 升高；若推理请求仍有充足 SLA slack，则可以降低其优先级，让出高优先级资源给高收益训练任务。

## 8. 统一优先级评分

对每个任务 $j$ 和候选优先级 $p$，CRISP 计算：

$$
Score_{j,p}(t)
=
\alpha \cdot norm(E_j(t))
+
\beta \cdot norm(S_j(t))
-
\gamma \cdot norm(I_{j,p}(t))
+
\eta \cdot A_j^{age}(t)
$$

其中：

- $norm(\cdot)$ 表示滑动窗口归一化；
- $\alpha$ 控制碎片化收益权重；
- $\beta$ 控制推理 SLA 保护强度；
- $\gamma$ 控制网络干扰惩罚；
- $\eta A_j^{age}(t)$ 为老化项，用于避免低收益任务长期饥饿。

最终选择：

$$
p_j^*(t)=
\arg\max_{p\in \mathcal{P}}
Score_{j,p}(t)
$$

并将任务级优先级映射到其 RDMA QP、flow 或 packet DSCP/PCP 标记。

## 9. 短时提权门控

CRISP 不允许任意任务直接进入高优先级队列。训练任务只有同时满足以下条件才可触发碎片化提权：

$$
G_j(t)>\theta_G
$$

$$
\hat{T}^{rem}_j(t)<\theta_T
$$

$$
I_{j,p}(t)<\theta_I
$$

$$
H_p(t)<\theta_H
$$

推理任务则以 SLA 压力为硬约束：

$$
S_j(t)>\theta_S
\Rightarrow
p_j^*(t)\ge p_{urgent}
$$

为了避免优先级频繁震荡，任务提权后设置最小保持时间 $\tau_{hold}$ 和最大提权时间 $\tau_{max}$。若收益下降、队列拥塞升高或达到最大提权时间，则立即降级：

$$
\text{Demote}(j)
\quad if \quad
G_j(t)\le \theta_G
\lor
I_{j,p}(t)\ge \theta_I
\lor
\tau_j^{boost}\ge \tau_{max}
$$

## 10. 调度流程

每个调度周期执行以下步骤：

1. 采集 GPU 占用、任务运行状态、链路利用率、队列长度、CNP/PFC 事件和推理外部 RTT。
2. 计算当前算网共同碎片化量 $F_{\text{cn}}(X_t)$。
3. 对每个运行中训练任务，模拟其完成后的状态 $X_t^{(-j)}$，计算 $G_j(t)$。
4. 使用历史生命周期分布、剩余通信量和队列等待估计 $\hat{T}^{rem}_j(t)$。
5. 计算单位时间碎片化收益 $E_j(t)$。
6. 对每个推理请求计算 SLA 压力 $S_j(t)$。
7. 对每个候选优先级队列估计插队代价和网络干扰 $I_{j,p}(t)$。
8. 计算 $Score_{j,p}(t)$，选择候选优先级。
9. 通过门控条件决定是否提权、保持或降级。
10. 将优先级写入 QP/flow/packet 标记，并更新 WRR 权重或严格优先级映射。

## 11. 伪代码

```text
Algorithm CRISP
Input: cluster state X_t, running jobs J, priority queues P
Output: priority assignment p_j for each job j

for each scheduling epoch t do
    collect C_t, N_t, Q_t, R_t
    F_now <- F_cn(X_t)

    for each job j in J do
        if j is training then
            X_release <- Release(X_t, j)
            G_j <- F_now - F_cn(X_release)
            T_rem_j <- EstimateRemainingTime(j, R_t, Q_t, N_t)
            E_j <- G_j / (T_rem_j + epsilon)
            S_j <- 0
        else if j is inference then
            G_j <- 0
            E_j <- 0
            S_j <- EstimateSlaPressure(j)
        end if

        best_score <- -inf
        best_p <- P_base(j)

        for each priority p in P do
            I_jp <- EstimateInsertionAndCongestionCost(j, p, Q_t, N_t)
            score <- alpha * norm(E_j)
                   + beta  * norm(S_j)
                   - gamma * norm(I_jp)
                   + eta   * Age(j)

            if score > best_score then
                best_score <- score
                best_p <- p
            end if
        end for

        if j is training then
            if G_j > theta_G and T_rem_j < theta_T
               and I_j,best_p < theta_I and QueueHeadroom(best_p) > theta_H then
                Promote(j, best_p, tau_max)
            else
                KeepOrDemote(j)
            end if
        else if j is inference then
            if S_j > theta_S then
                Promote(j, max(best_p, p_urgent), tau_sla)
            else
                AssignSlackAwarePriority(j, best_p)
            end if
        end if
    end for

    update QP priority / DSCP / WRR weights
end for
```

## 12. 与已有方法的区别

CRISP 与 Fixed Priority 的区别在于，优先级不再由任务类型静态决定，而是由当前资源释放收益、SLA 压力和网络干扰共同决定。

CRISP 与 Queue-aware Dynamic Priority 的区别在于，它不只优化队列等待时间，还显式考虑任务完成后对未来可调度性的影响。

CRISP 与 CRUX-like 的区别在于，它不把 GPU 数量或 GPU 强度等同于调度价值。少卡任务如果占据关键主机或 ToR 位置，并且即将完成，也可能获得短时提权；大卡任务如果剩余时间长或干扰过高，则不会长期占用高优先级队列。

CRISP 与 Frag-routing only 的区别在于，它不仅在路径选择阶段保护资源块，还通过通信优先级改变任务完成顺序，从运行时资源释放轨迹上降低碎片化。

## 13. 与 PD-MoE 专家放置实验的关系

当前已经完成的 PD-MoE 专家放置实验可以视为 CRISP 主线中的“推理通信子模块验证”。该实验没有直接启用训练任务短时提权，也没有完整评估 $G_j(t)$、$S_j(t)$ 与 $I_{j,p}(t)$ 的三项联合评分；但它验证了两个对 CRISP 仍然重要的事实。

第一，运行时通信调度会显著改变资源释放轨迹。在 PD=3:1、`EXPERT_NUM=48`、64 个长请求的实验中，全 default baseline 在截止时间内仅完成 `61/64` 个任务，而 tuned 策略完成 `64/64`。这说明通信路径、专家副本结构和本地队列顺序会影响任务是否能及时释放 placement，从而影响后续任务可调度性。

第二，本地队列状态是连接网络性能与资源状态的关键中间变量。该实验中 tuned 策略将本地 flow 队列均值降低约 `48.3%`，TTFT 降低约 `71.6%`，TPOT 降低约 `75.5%`。这与 CRISP 的核心假设一致：调度器不应只看单个流的 FCT，而应关注队列变化如何推动任务完成顺序和资源释放轨迹。

因此，后续 CRISP 实验可以把 PD-MoE tuned 策略作为推理侧默认通信策略，再叠加训练任务的碎片化收益提权。实验设计上应区分两类收益来源：

- 推理子模块收益：专家放置、route probe、本地 flow queue 和 PD split 带来的 TTFT/TPOT 改善；
- 训推混部收益：CRISP 根据碎片化释放收益和 SLA 压力改变任务级完成顺序带来的 $F_{\text{cn}}(t)$ 与未来可调度性改善。

## 14. 参数建议

建议初始参数如下：

- 调度周期：500 us 或 1 ms；
- $\theta_T$：任务剩余时间 P20 到 P30 分位；
- $\theta_G$：最近窗口 $G_j$ 正值分布的 P70；
- $\theta_I$：高优先级队列水位或 CNP 强度的 P80；
- $\tau_{hold}$：2 到 3 个调度周期；
- $\tau_{max}$：10 到 20 个调度周期；
- $\alpha:\beta:\gamma:\eta$：训练主导场景可设为 `4:2:3:1`，推理主导场景可设为 `2:5:3:1`。

这些参数应结合实验文档中的网络负载强度、训推混合比例、初始碎片化程度、SLA 紧迫程度和优先级队列数量进行扫描。

## 15. 评价方式

CRISP 的有效性应从三类指标验证：

- 碎片化与可调度性：平均/P95 $F_{\text{cn}}(t)$、$\int F_{\text{cn}}(t)dt$、完整 8-GPU 主机数量、同 ToR 可用资源块数量、未来任务可调度成功率、碎片化导致的阻塞率；
- 任务性能：训练 JCT、P95/P99 JCT、iteration time、GPU network idle time、推理 P95/P99 响应时延、TTFT、SLA violation ratio；
- 网络稳定性：FCT、coflow completion time、各优先级队列等待时间、高优先级队列占用率、链路利用率、CNP/PFC 数量、队列长度分布。

消融实验至少包含：

- w/o Frag Gain：去掉 $G_j(t)$，验证碎片化收益信号贡献；
- w/o Remaining Time：直接使用 $G_j(t)$，验证单位时间收益和短时提权的必要性；
- w/o SLA Bias：去掉 $S_j(t)$，验证推理 SLA 保护项；
- w/o Insertion Cost：去掉 $I_{j,p}(t)$，验证插队代价与 PFC 风险控制；
- w/o Aging：去掉老化项，验证长期公平性。

## 16. 预期效果

CRISP 预期能够在不显著增加推理 SLA violation ratio 和 PFC 事件的前提下，降低平均与 P95 算网共同碎片化量，提高完整高速互联资源块数量，并改善未来任务可调度成功率。相比只看队列状态或 GPU 强度的动态优先级算法，CRISP 的主要收益来自对任务释放轨迹的主动控制：它让网络调度从“服务当前流”扩展为“塑造未来资源形态”。
